# dt-handbook — 코드 인수인계 핸드북 PDF 생성 스킬 설계

> 작성 2026-09-14 · 상태: 설계 확정(구현 전) · 산출 스킬 `dt-handbook`
> 선례: `2026-09-12-user-guide-skill-design.md`(dt-guide — 파이프라인·게이트·PDF 골격을 승계)

## 1. 무엇을 만드나

프로젝트 소스코드를 분석해 **신규 개발자가 코드 전반을 파악할 수 있는 인수인계 수준의 설명서**를
PDF 로 낸다. 기술 스택, 핵심 아키텍처, 데이터 관리 주체와 프로토콜, 데이터 흐름, 시나리오별
함수 호출까지를 도표·그림·표로 담는다.

`dt-guide` 와 독자가 다르다. `dt-guide` 는 제품을 쓰는 사람에게 화면 사용법을 알려 주고,
`dt-handbook` 은 코드를 물려받는 개발자에게 구조와 이유를 알려 준다.

### 1-1. 왜 만드나

기존 스킬로는 이 자리가 안 메워진다. `dt-audit` 은 스펙과 구현의 어긋남을 진단하고,
`dt-spec`·`dt-bespec` 은 앞으로 만들 것을 규정하며, `dt-guide` 는 사용자를 향한다.
"이미 만들어진 코드가 왜 이 모양인지"를 사람에게 설명하는 문서는 없다.

외부에도 대체재가 없다. 조사한 공개 스킬(oh-my-mermaid, design-doc-mermaid, C4 다이어그램
스킬 등)은 전부 다이어그램 생성기이고, 근거 고정·낡음 방지·PDF 산출이 없다.

## 2. 불변 원칙

1. **정적 축이 먼저다.** 아키텍처는 데이터의 관리 주체, 코드가 뭉친 곳, 그렇게 된 이유로
   이루어진다. 시나리오는 그 위에 얹는 층이지 척추가 아니다. 3·4·5·7장은 시나리오를 하나도
   뽑지 않아도 완성된다(G4 가 강제).
2. **조율자는 원자료를 읽지 않는다.** 코드 분석은 워커 컨텍스트에 가둔다. 조율자가 여는 파일은
   설정·인벤토리·`structure.json`·`handbook.md`·영수증뿐이다.
3. **질문은 조율자만 한다.** 워커는 `needsDecision` 으로 올린다.
4. **근거 없는 단정을 쓰지 않는다.** 코드 근거·문서 근거·추정을 라벨로 가른다(§6-3).
5. **범용이다.** 특정 프로젝트·특정 스택을 전제하지 않는다. 스크립트는 힌트를 주고 판단은
   워커가 한다.
6. **리뷰는 격리·1회.** `ko-writing-reviewer`(`docType: 'handbook'`), 재리뷰 없음.
7. **게이트 먼저.** G0~G9 를 통과해야 PDF 를 낸다. 낡은 문서로 만든 PDF 는 나가지 않는다.
8. **외부 지식 원천은 선택이다.** Atlassian MCP 가 없어도 문서는 나온다. 없으면 품질만 낮아진다.

## 3. 문서 뼈대 — 8장

arc42 를 부분집합으로 흡수하되 빈칸이 생기지 않게 인수인계 목적으로 재단했다. C4 는 그림
규약으로만 쓴다. 문서 유형은 Diátaxis 의 explanation 이다 — 절차 지시가 스며들면 망가진다.

| 장 | 내용 | 그림 | 근거 |
|---|---|---|---|
| 표지 | 제품명·버전·생성일·전권/발췌 표시 | 손 SVG | — |
| 1. 5분 요약 | 무엇을 하는 물건인가, 누가 쓰나, 큰 덩어리 3~5개 | 손 SVG | 절 단위 |
| 2. 무엇으로 만들었나 | [영역·무엇·버전·왜]·[경로·책임·여기 안 넣는 것]. 기동 절차는 링크만 | 없음 | 절 단위 |
| 3. 바깥과 주고받는 것 | C4 L1. 바깥에 무엇이 있고 무엇을 주고받나. 신뢰 경계 | 머메이드 | 절 단위 |
| 4. 코드가 나뉜 모양 | C4 L2/L3. 모듈 그래프 + 계층 호출 규칙 표 + 실제 위반 | 머메이드 | 절 단위 |
| 5. 데이터는 누가 관리하나 | [데이터·주인·저장소·수명·바꾸는 주체·옮기는 방법] + ERD | 손 SVG + 머메이드 | **인라인** |
| 6. 기능별 동작 순서 | 요약·시퀀스·함수 호출 표·실패 경로 | 머메이드(+손 SVG 상위 3개) | **인라인** |
| 7. 전체에 공통으로 걸리는 것 | 인증·에러·설정·상태·테스트·성능. [규약·구현 위치·예외] | 필요 시 머메이드 | 절 단위 |
| 8. 주의할 점과 남은 일 | [함정·원인·증상·회피법] + 부채 목록 + 확장 지점 | 없음 | 절 단위 |

6장 시나리오 하나의 고정 배치: ① 한 줄 요약과 진입점 ② 시퀀스 다이어그램 ③ 함수 호출 표
[순서·호출·`파일:줄`·하는 일·넘기는 데이터] ④ 실패 경로.

**의도적으로 뺀 것**: arc42 의 품질 요구·용어집·ADR 전용 장. 품질 요구는 코드에서 역추출이
안 되고, 용어집은 앞에 몰면 안 읽히므로 D4 대로 첫 등장 자리에서 푼다. 결정 근거는 별도 장
대신 D1·D2 로 각 장에 녹인다.

## 4. 분석 — 두 축

### 4-1. 정적 축 (`structure.json`)

진입점과 무관하게 구조 자체에서 뽑는다.

1. **코드가 뭉쳐 있는 곳** — import 그래프의 결합 강도로 군집을 찾는다. 디렉터리 구조와
   어긋나면 그 자체를 발견으로 문서에 적는다.
2. **데이터의 주인** — 저장소에 **쓰는 지점**을 전부 모은다(DB 쿼리·파일 쓰기·스토어 갱신·
   IPC 송신·캐시 무효화). 한 데이터에 쓰기 주체가 둘 이상이면 결함 후보로 5장에 명시한다.
3. **경계** — 프로세스·네트워크·저장소·신뢰 경계. 경계를 넘는 지점마다 프로토콜을 기록한다.
4. **핫스팟** — 파일 크기 + git 변경 빈도 + 함께 바뀌는 파일 쌍(co-change).
5. **왜 이렇게 됐나** — git 커밋 메시지·주석·기존 설계 문서·(있으면) 외부 지식 원천에서
   모은다. 못 찾으면 추정 라벨로 남긴다. 지어내지 않는다.

### 4-2. 동적 축 (`traces/<flow>.json`)

시나리오 선정 순서: ① 기존 e2e 시나리오 원장·`docs/specs` 가 있으면 수입 ② 없으면 진입점
(라우트·IPC 핸들러·HTTP 엔드포인트·CLI 명령)에서 호출 깊이·분기 수로 랭킹 ③ `--flow` 인자가
있으면 언제나 덮어쓴다. 기본 상한 8개(`--max-flows`).

정적 축의 핫스팟을 지나는 흐름에 가산점을 준다. 반대로 추적 결과는 정적 축의 추정 간선을
확증한다. 의존 방향은 정적 → 동적 한쪽뿐이다.

### 4-3. 외부 지식 원천 (선택)

Atlassian MCP(`mcp__atlassian__*`)가 붙어 있으면 코드에서 안 나오는 것을 보강한다 — 스택 선택
이유(2장), 경계가 생긴 계기(4·5장), 요구사항 원문(6장), 열린 버그·미완 작업(8장), 검토했다
버린 안(D2).

- 질의 상한: 항목당 상위 5건(`maxHitsPerTopic`), 키워드는 모듈명·시나리오명.
- 미연결이면 **한 번만** 안내하고 그대로 진행한다. 인증 만료·권한 부족이면 받은 오류를 그대로
  보이고 진행한다. 값을 지어내지 않는다. `enabled: "off"` 면 확인도 안내도 하지 않는다.
- 무인 실행에서는 안내를 기록만 한다.
- 표지 뒷면에 [원천·쓴 범위·조회 시각]을 남긴다.

## 5. 실행 흐름

```
/dt-handbook                §0 설정 → §1 analyze → [CP1 구조] → [CP2 시나리오]
                            → §2 trace → §3 write → 한글 리뷰 → [CP3 초안] → §4 build
/dt-handbook analyze|trace|write|build     그 단계만
--flow "로그인, 문서 저장"    그 시나리오만 (6장만 갱신)
--area src/main/ipc          그 모듈만 (4·5장만, 추적 안 함)
--section 5,6                그 장만
--pdf-only-section 6         발췌본 PDF 를 하나 더 낸다
--max-flows N                시나리오 상한 (기본 8)
--shots                      화면 캡처를 곁들인다 (dt-guide 캡처 엔진 재사용)
--no-figures                 그림 없이 초안 확인용 빌드 (배포용 아님)
--unattended                 무인
```

산출물은 **한 권을 계속 키운다**. `--flow` 를 줘도 `handbook.md` 한 파일의 해당 절만 갱신하고,
PDF 는 전권으로 낸다. 조각 배포가 필요하면 `--pdf-only-section` 으로 발췌본을 따로 뽑되,
발췌본에는 "전권 vN 에서 뽑음" 표시를 박는다.

### 워커

| 워커 | 하는 일 | 반환 |
|---|---|---|
| `handbook-analyst` | 정적 축 전담. 스크립트 결과 위에서 군집·데이터 주인·경계·핫스팟·시나리오 후보를 판정 | `inventoryPath`·`structurePath`·`needsDecision` |
| `handbook-tracer` | 시나리오 하나의 호출 사슬과 실패 경로 (시나리오당 1 dispatch, 병렬) | `tracePath`·`needsDecision` |
| `handbook-author` | 8장 집필과 그림 생성. 변경 없는 장은 다시 쓰지 않는다(장 단위 해시) | `draftPath`·`coverage`·`gate`·`figures` |
| `ko-writing-reviewer` | 기존 워커 재사용 (`docType: 'handbook'`) | `verdict`·`findings` |

추적을 집필에서 떼는 이유는 두 가지다. 시나리오 하나가 워커 컨텍스트 하나를 통째로 먹고,
`--flow` 재실행 때 이 단계만 다시 돌면 되기 때문이다.

### 체크포인트 3개

1. **구조 승인** — 군집·데이터 주인·경계·핫스팟 표.
2. **시나리오 목록 승인** — 몇 개를 어디까지 팔지. 문서 비용이 여기서 정해진다.
3. **초안 승인** — 본문·그림·한글 리뷰 결과·못 담은 항목.

설정 질문·MCP 안내·캡처는 체크포인트가 아니라 확인이다. 무인 실행에서는 기본값으로 대신하고
`assumed` 로 기록한다.

## 6. 문체 — `docType: 'handbook'`

`docs/refs/readable-writing.md` 에 절을 추가한다. 새 규칙집을 만들지 않는다.

### 6-1. 그대로 유지
B2 능동태·주어 살리기 · B3 명사화 풀기 · B4 한 문장 한 개념 · C2 번역투 10종 ·
C3-c 개발자 구어 · C4 AI 상투구.

### 6-2. 완화

| 규칙 | 사용자 문서 | 핸드북 |
|---|---|---|
| A1 약어 풀이 | 전부 풀이 | 일반 개발 상식(API·DTO·IPC·DOM·CI)은 면제. 이 프로젝트에서만 통하는 말만 풀이 |
| C3 낯선 용어 치환 | 개발 용어까지 일상어로 | 개발 용어는 그대로. 순수 문체 항목만 유지(`수행하다`→`하다`) |
| C1 의인화 | 판단·결정 동사 금지 | 알고리즘 서술은 허용(`라우터가 경로를 결정한다`). `앱이 사용자를 이해한다`는 여전히 위반 |

### 6-3. 추가 (D1~D5)

- **D1. 왜를 비우지 않는다.** `이 계층은 IPC 로만 통신한다` → `렌더러에 파일 접근 권한을 주지
  않으려고 IPC 로만 통신한다`.
- **D2. 대안과 반례를 적는다.** `직접 호출로도 되지만, 창이 여러 개일 때 순서가 깨져서 큐를 뒀다`.
- **D3. 단정에는 근거, 추정에는 라벨.** 뱃지 세 가지 — `[코드]`(`파일:줄`) · `[문서]`(Jira 키·
  Confluence 링크) · `[추정]`. **이모지를 쓰지 않는다**(PDF 임베드가 불안정하다).
- **D4. 코드 식별자는 번역하지 않는다.** `UserService.create()` 는 그대로. 개념어만 한글 우선에
  첫 등장 영문 병기 — `이벤트 루프(event loop)`.
- **D5. 지시문 금지.** `설정하세요`·`실행합니다` 같은 절차문이 나오면 설명서가 매뉴얼로 변질된
  신호다. 절차는 링크로 넘긴다.

문체는 평서체(`~한다`). 근거 밀도는 5·6장 인라인, 나머지 장은 절 단위다.

## 7. 그림 파이프라인

```
handbook.md
  → 마크다운 렌더러  ① 원시 HTML/SVG 블록 통과 허용  ② ```mermaid 펜스 → <pre class="mermaid">
  → handbook-theme.html (폰트 동봉 + 도형 키트 CSS)
  → Chromium  ③ 동봉 mermaid.min.js 로 렌더 → 검사 → print → PDF
```

- **머메이드 동봉** — `templates/vendor/mermaid-<버전>.min.js`, 버전 고정, CDN 금지. npm 의존이
  아니라 정적 자산이므로 "런타임 의존성 0" 정책은 유지된다. MIT 출처·버전을 파일 상단에 박는다.
- **PDF 안에서 벡터로 굳는다** — 완성 PDF 에는 자바스크립트도 네트워크 요청도 없다. 확대해도
  안 깨지고 그림 속 글자가 검색된다. 폰트는 `templates/fonts` 의 동봉 폰트를 써서 Chromium 이
  부분집합을 임베드하게 한다(시스템 폰트 이름만 적으면 남의 컴퓨터에서 한글이 깨진다).
- **도형 키트** — `templates/handbook-figures.css`. 인쇄용 고정 팔레트(흑백에서도 명도로 구분),
  의미를 지는 색은 문서 전체에서 하나. 도형 어휘 8종(박스·저장소·외부 시스템·경계선·레인·
  라벨 붙은 화살표·번호 뱃지·주석 말풍선) 밖으로 안 나간다. 그리드 8px, 글자 11~13px.
- **견본** — `references/figure-examples.md` 에 완성본 3개(표지·5분 요약·데이터 주체 지도).
  집필 워커는 빈 종이가 아니라 이것을 보고 채운다. 첫 판 품질이 사실상 이 파일에 달려 있다.
- **그림 규칙**(`artifact-diagramming` 승계 + 인쇄 적응) — 이름이 아니라 작동 방식을 그린다 ·
  화살표에 라벨 · 한 그림 한 주장 · `<figure>`+`<figcaption>` 필수 · SVG 안 `script`/`style`/
  `foreignObject` 금지 · A4 폭 초과 금지 · `break-inside: avoid` · 문장이 더 빠르면 안 그린다.
- **손 SVG 상한 6장**(고정 3 + 시나리오 3). 상한이 없으면 판마다 결과가 달라진다.
- **화면 캡처(`--shots`)** — 캡처 위에 라벨을 얹지 않는다(캡처가 바뀌면 어긋난다). 아래에
  표 [화면 요소 · 담당 컴포넌트 `파일:줄`] 을 붙인다.
- **폴백** — 머메이드를 못 띄우면 배포용 PDF 를 내지 않는다. 오류를 그대로 보이고 `--no-figures`
  를 안내한다. 그림을 PNG 로 굽는 방식은 확대 품질과 검색을 잃으므로 최후 수단이다.

## 8. 게이트

| | 막는 것 |
|---|---|
| G0 전제 | 설정·front matter·`inventory.md`·`handbook.md` 부재 |
| G1 버전 | front matter 버전이 `package.json` 과 어긋남 |
| G1-b 본문 수치 | 본문에 박힌 버전·파일명·수치가 실제와 어긋남 |
| G2 정합 | 인벤토리의 모듈·시나리오 id 누락 또는 문서에만 있는 유령 항목 |
| G3 근거 | 인라인 `파일:줄` 의 파일·심볼 실재 여부(5·6장), 절 단위 근거 파일 존재(나머지) |
| G4 자립성 | 6장에만 등장하는 모듈·데이터가 4·5장에 없음 |
| G5 그림 | 머메이드 문법, A4 폭 초과·잘림, 캡션 없음, SVG 안 스크립트, 손 SVG 6장 초과 |
| G6 문체 | `koWritingLint`(handbook 모드) · 이모지 · 지시문(D5) |
| G7 리뷰 영수증 | 한글 리뷰 미수행 또는 리뷰 뒤 본문 수정(`bodyHash` 불일치) |
| G8 유출 | 코드 인용·캡처 속 토큰·키·이메일·사내 호스트. `audience: external` 이면 Jira 키·Confluence 링크도 |
| G9 신선도 | 분석 기준 커밋 이후 대상 파일이 바뀌었는데 문서를 안 고침 |

**G3 의 심볼 검사 방법** — AST 파싱까지 가지 않는다. 인용한 `파일:줄` 의 파일을 열어 그 부근
(앞뒤 20줄)에서 인용한 식별자를 문자열로 찾는다. 줄 번호는 어긋나도 식별자가 파일 안에 있으면
경고(줄 번호 갱신 안내)로 낮추고, 파일 전체에서 식별자가 사라졌을 때만 막는다. 정확도를 조금
포기하는 대신 어떤 언어에서도 돌고 오탐이 적다.

**G1-b 를 새로 넣는 이유** — 기존 가이드 게이트가 front matter 만 보고 본문은 안 봐서 본문
수치·파일명이 낡은 채로 통과하는 구멍이 확인돼 있다. 같은 구멍을 물려받지 않는다.

**G9 가 이 스킬의 존재 이유다.** 코드 설명서는 코드보다 낡는 방식으로 죽는다. `structure.json`
·`traces/*.json` 에 분석 기준 커밋을 박아 두고 빌드 때 비교한다.
- 인용한 심볼이 사라짐 → 막는다. 그 문장은 이제 거짓이다.
- 파일이 바뀌기만 함 → 경고하고 다시 돌릴 명령을 찍어 준다(`/dt-handbook trace --flow 로그인`).
- 안 바뀜 → 조용히 통과.

## 12. 검증 (구현 1단계에서 먼저 한다)

표본 PDF 를 실제로 만들어 확인하고 결과를 보고한다. 안 되면 폴백을 재검토한다.
1. 한글 폰트가 PDF 에 임베드되는가.
2. 머메이드가 벡터로 들어가고 확대·검색이 되는가.
3. 다른 뷰어(미리보기·Acrobat·크롬·모바일)에서 같게 보이는가.
4. 손 SVG 가 A4 폭 안에서 잘리지 않는가.

## 13. 실패·폴백

- **워커를 못 쓰면** 조율자가 각 워커 파일의 「할 일」을 직접 밟고 한 줄 고지한다(inline degrade).
- **추적이 진입점에서 막히면**(동적 디스패치·리플렉션 등) 그 시나리오는 `partial` 로 표시하고
  거기까지만 적는다. 이어지는 흐름은 `[추정]` 라벨로 쓰거나 비운다. 지어내지 않는다.
- **화면 캡처를 못 하면** 캡처 없이 간다(`--shots` 무시, 기록).
- **git 이력이 얕으면**(shallow clone 등) 핫스팟·co-change 를 비우고 그 사실을 2장에 한 줄로
  적는다. 없는 값을 추측하지 않는다.
- **시나리오를 하나도 못 뽑으면** 6장을 비우고 나머지 7개 장으로 문서를 낸다. 원칙 1 대로
  정적 축은 시나리오 없이도 자립한다.
- **무인 실행** — 질문은 기본값으로 답하고 `assumed` 라벨을 붙인다. 체크포인트는 자동 승인으로
  기록한다. 마지막에 [항목·고른 값·사유] 표로 가정 목록을 보인다.

## 14. 하지 않는 것

- 코드를 고치지 않는다. 읽기 전용이다(쓰기는 `docs/handbook/` 과 설정 파일뿐).
- 스펙 문서를 대체하지 않는다. `dt-spec`·`dt-bespec` 은 앞으로 만들 것을, 이 스킬은 이미 있는
  것을 설명한다.
- 아키텍처를 평가하지 않는다. 규칙 위반은 사실로 적되 점수를 매기지 않는다(그건 `dt-review`).
- 절차서를 겸하지 않는다(D5).
