# 에이전트 비용 기준선 (GEN-41)

> 측정 도구: `node scripts/agentCost.mjs <세션 폴더> [--match <정규식>] [--files] [--json]`. 세션 폴더는 `~/.claude/projects/<프로젝트>/<세션 id>/`다.
> 환산 비용 = 입력 1 · 캐시 쓰기 1.25 · 캐시 읽기 0.1 · 출력 5의 가중합(입력 토큰 기준). 요금표가 바뀌면 `WEIGHTS`를 고친다.

## 1. 읽는 법

에이전트는 턴마다 그때까지 쌓인 맥락 전체를 다시 읽는다. 대부분 캐시로 읽어 싸지만, 턴이 많고 맥락이 크면 그 곱이 비용이 된다. 그래서 볼 숫자는 셋이다.

- **턴 수** — 도구를 부를 때마다 한 턴.
- **시작 맥락** — 첫 턴의 맥락(시스템 지시 + 에이전트 정의 + 받은 지시). 지금은 어느 에이전트든 약 33k다.
- **최대 맥락** — 일하면서 읽은 문서·도구 결과·자기가 쓴 파일이 쌓인 크기.

## 4. 원인 — spec-author 39턴을 펼쳐 본 것

| 턴 | 한 일 | 맥락 |
|---|---|---|
| 1~10 | 지시 문서 읽기. `dt-spec-generate-spec/SKILL.md`(2.6만 자)를 두 번 읽었고, 참조 문서 9개를 통째로 읽었다 | 34k → 97k |
| 11~16 | 프로젝트와 추출 결과(`extraction.json`) 보기 | → 119k |
| 17~26 | **플러그인 스크립트 소스 읽기.** 헤더를 만드는 `buildSpecHeader.mjs`에 명령줄이 없어서 소스를 열고 `node -e import(…)`로 불렀다. 그 김에 `validateSpec.mjs`(1.3만 자)·`projectContextSync.mjs`도 읽었다 | → 144k |
| 27~34 | 스펙 네 파일 쓰기(쓴 내용도 맥락에 쌓인다) | → 176k |
| 35~38 | 한글 검사 지적을 한 건씩 따로 고치기 | → 184k |

다른 에이전트도 같은 모양이다. definition-author는 `definitionVersion`·`validateDefinition`·`checkDefinitionDrift` 소스를, bespec-author는 `buildSpecHeader`·`validateSpec` 소스를 읽었다. 같은 파일을 다시 읽은 횟수는 에이전트마다 0~6번으로 크지 않았다. 비용을 키운 것은 **큰 맥락 × 많은 턴**이다.

재결속 두 번(v2 재결속, 합계 환산 약 20만)은 정의서 버전만 올라 헤더 한 줄을 바꾸는 일이었다.

## 5. 절감안 (적용함)

1. **헤더 명령줄** — `scripts/buildSpecHeader.mjs`·`scripts/buildDefinitionHeader.mjs`를 명령으로 실행한다. `--replace <파일>`은 헤더 줄만 바꾸고 다른 주석(`origin` 따위)은 남긴다. 빠진 값은 지금 헤더에서 가져온다.
2. **작성 에이전트 규칙 세 줄**(spec-author·bespec-author·definition-author·adopt-extractor·plan-author) — 플러그인 스크립트 소스를 읽지 않는다 / 같은 문서를 두 번 읽지 않고 필요한 절만 읽는다 / 읽기·고치기를 묶는다. 별도 문서로 빼지 않았다 — 읽을 문서가 하나 더 느는 것도 비용이다.
3. **버전만 오른 재결속은 에이전트 없이** — 드리프트 검사가 0이면 조율자가 `buildSpecHeader.mjs --replace <파일> --definition <경로>@v<N>`만 돌린다(`docs/refs/spec-pipeline.md` §5-5, `skills/dt-adopt/SKILL.md` 6.5).

## 6. 다시 잰 결과 (2026-11-27)

§3과 같은 입력(같은 기획서·정책 PDF, `.dt.json`)으로 정의서 작성을 처음부터 다시 돌렸다. 조율자 답도 같은 방침이다 — 전부 권장안을 고르고, 운영 시간·글자 수 한도·사내 도메인·내 예약 경로만 같은 값으로 직접 답했다. 질문은 두 라운드였다.

| | 턴 | 시작 맥락 | 평균 맥락 | 최대 맥락 | 출력 | 처리 합계 | 환산 비용 | 시간 |
|---|---|---|---|---|---|---|---|---|
| 전 (§3) | 30 | 36k | 105k | 145k | 55k | 3.20M | 735k | 9분 |
| 후 | 31 | 33k | 89k | 121k | 42k | 2.79M | 625k | 8분 |
| 차이 | +1 | | −15% | −17% | −24% | −13% | **−15%** | |

- **스크립트 소스를 읽지 않았다.** 전에는 `buildDefinitionHeader.mjs` 소스를 열었다. 이번에는 헤더를 `buildDefinitionHeader.mjs --replace`로 바꿨다.
- **품질 게이트는 그대로 통과했다.** `validateDefinition` `valid: true`, `status: finalized`, IF 12개 모두 `컨벤션`, 한글 검사 지적 0.
- 에이전트가 `validateDefinition` CLI가 아무것도 출력하지 않는다고 두 번 짚었다(그래서 함수를 직접 불렀다 — 소스를 읽게 만드는 것과 같은 원인). 이번에 결과 JSON 출력과 종료 코드를 붙였다.
- 같은 문서를 다시 연 것은 3번이다(`dt-devspec/SKILL.md` 2번, `ux-sources.md` 2번). 절 단위로 나눠 읽은 것이라 규칙 위반으로 보지 않았다.

**한계.** 전후 한 번씩만 돌렸다. 질문 수도 23개 → 14개로 달라졌다(모델이 묶는 방식이 실행마다 다르다). 그래서 −15%에는 실행 사이의 편차가 섞여 있다. 재결속을 에이전트 없이 하는 절감(§5-3, adopt 흐름 환산 약 20만)은 돌려서 잰 값이 아니다. 그 두 번의 dispatch가 없어지는 만큼으로 계산했다.
