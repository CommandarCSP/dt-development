# 스택 설정이 없으면 만든다 — 절차 SOT

`.dt-frontend.json` · `.dt-backend.json` 이 없는 프로젝트에서 스택 스킬이 **물러나지 않고 만들고 계속하는** 절차다. 스킬 8개가 이 문서를 가리킨다 — 절차를 각자 베껴 쓰면 한쪽만 고쳐지는 사고가 난다.

## 왜 필요한가

이 설정 파일은 **스캐폴드로 새 프로젝트를 만들 때만** 생겼다(`dt-frontend-scaffold/checklist/new-project.md`). 이미 있는 프로젝트에 플러그인만 얹으면 아무도 만들어 주지 않는다.

그때 어떻게 되는지가 문제의 핵심이다. **코드는 멀쩡히 돈다** — `overrides.mjs` 는 파일이 없으면 빈 `Set` 을 돌려주고, `modes/full.mjs` 는 읽기에 실패하면 기본값으로 간다. 막는 것은 **스킬 문서의 문장**이었다: "`.dt-frontend.json` 이 있는 프로젝트에서만 의미가 있습니다." 그래서 오류도 안 나고, 설치한 사람은 플러그인이 도는 줄 알지만 절반이 조용히 비켜 있었다.

이 절차는 그 문장을 "없으면 만들고 계속한다" 로 바꾸기 위한 것이다.

## 언제 부르나

스택 스킬(`dt-frontend-*` · `dt-backend-*`)이 **실제로 일을 시작하기 직전**, 그 스택의 설정 파일이 없을 때. 미리 만들지 않는다 — 플러그인을 설치만 하고 안 쓰는 프로젝트에 파일을 남기지 않는다.

## 절차

### 1. 스택을 가린다

`<projectRoot>/package.json` 을 읽어 `${CLAUDE_PLUGIN_ROOT}/scripts/detectStackConfig.mjs` 의 `detectStacks(pkg)` 에 넘긴다. 실행 파일이 아니라 모듈이라 import 해서 쓴다.

- `react` · `react-dom` · `next` · `vite` → `frontend`
- `@nestjs/core` · `@nestjs/common` → `backend`
- 둘 다 잡히면 둘 다 만든다(모노레포 루트 등)

**빈 배열이면 만들지 않는다.** 감지 실패는 오류가 아니라 "모른다" 다. 억지로 하나를 고르면 엉뚱한 규칙이 켜진 채 리뷰가 돈다. 이때는 사용자에게 "스택을 알 수 없어 설정을 만들지 않았다" 고 알리고 스킬을 그만둔다.

### 2. 소스 경로를 찾는다

`src/` 가 있으면 `src`. 없으면 `package.json` 이 있는 자리를 기준으로 소스 폴더를 찾는다. 모노레포면 `packages/web/src` 같은 값이 된다.

### 3. 만들고 **무엇을 정했는지 보고한다**

`buildStackConfig(stack, { srcPath })` 결과를 `CONFIG_FILE_NAME[stack]` 로 쓴다. 템플릿(`templates/dt-frontend.json.tmpl` · `dt-backend.json.tmpl`)과 같은 모양이며, 둘이 갈리지 않는 것은 테스트가 지킨다.

**묻지 않는다. 대신 반드시 한 줄로 보고한다.**

```
.dt-frontend.json 을 만들었습니다 — React 프로젝트로 보았고 소스는 src/ 로 잡았습니다.
모노레포처럼 소스가 다른 곳에 있으면 paths.src 를 고쳐 주세요.
```

보고를 빠뜨리면 안 된다. **감지가 틀릴 수 있는 자리**이고(모노레포에서 `src/` 로 잘못 잡으면 리뷰가 엉뚱한 곳을 본다), 남의 저장소 루트에 파일이 하나 생기는 일이다. 묻지 않기로 한 만큼 알리는 것으로 갚는다.

### 4. 하던 일을 계속한다

설정이 생겼으니 스킬은 원래 하려던 일을 그대로 한다. 사용자에게 다시 명령을 치게 하지 않는다.

## 만들지 않는 경우

- **1번에서 스택을 못 가렸을 때** — 위 참조
- **파일이 이미 있을 때** — 손대지 않는다. `enabledSkills` 에 자기가 없어도 추가하지 않는다. 그건 사용자가 일부러 끈 것일 수 있다

## 이 절차가 건드리지 않는 것

- **코드의 게이트를 새로 만들지 않는다.** 지금 코드가 설정 없이도 도는 것은 미덕이다. 이 절차는 문서 게이트만 푼다
- `paths` · `enabledSkills` 를 코드가 강제하게 바꾸지 않는다. 현재 코드가 실제로 읽는 키는 `coverage` 와 `overrides` 뿐이다
- 새 슬래시 커맨드를 만들지 않는다. 필요한 시점에 생기면 사용자가 칠 명령이 없다
