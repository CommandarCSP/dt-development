# 호환 정책 — 버전의 뜻과 산출물 형식

플러그인을 올렸을 때 **이미 있는 프로젝트 파일**(스펙·정의서·project-context·설정 등)이 어떻게 되는지 정한다. 변경 기록은 `CHANGELOG.md`, 산출물 형식의 목록·판정·이전은 `scripts/artifactSchemas.mjs`가 단일 출처다.

## 1. 플러그인 버전 (x.y.z)

| 올리는 자리 | 언제 |
|---|---|
| **major** (x) | 이전 도구 없이 기존 산출물이 깨지는 형식 변경, 스킬·명령 이름을 바꾸거나 없앰, 설정 키의 뜻을 바꿈 |
| **minor** (y) | 기능 추가, **이전 도구가 있는** 산출물 형식 변경, 새 설정 키 |
| **patch** (z) | 고침·문서. 산출물 형식은 그대로 |

1.0.0 전(0.y.z)에는 minor가 major 역할도 한다 — 형식이 깨지면 minor를 올리고 CHANGELOG의 **산출물 형식 변경** 절에 굵게 적는다.

버전 올리기는 `node scripts/release.mjs <patch|minor|major|x.y.z> [--write]` 하나로 한다(버전이 적힌 4곳 + CHANGELOG). 커밋·태그(`v<x.y.z>`)는 사람이 확인한 뒤 한다.

## 2. 산출물 형식 버전

산출물마다 형식 버전이 있다. 표시하는 법은 하나로 둔다.

| 산출물 | 표시 |
|---|---|
| 스펙 5종(requirements·design·tasks·layout-skeleton·api-contract) | 머리 `<!-- specVersion: 1.1 -->`(기존) |
| 정의서 `definition.md` | 머리 `<!-- specVersion: 1.2 -->`(기존) |
| 그 밖의 md(project-context·interactions·plan·e2e 원장·결정 기록) | `<!-- dt-schema: <종류>@<N> -->` |
| 설정 json(`.dt.json`·`.dt-frontend.json`·`.dt-backend.json`) | 최상위 `"$schemaVersion": N` |

- **표시가 없는 파일은 깨뜨리지 않는다.** 형식에 옛 특징(예: 스택 접두어 없는 `## 기술 스택`)이 있으면 그 옛 버전, 없으면 현재 버전으로 본다. 표시를 강제하지 않는 이유: 이미 쓰고 있는 프로젝트가 한꺼번에 막힌다(GEN-22에서 겪음).
- 새로 쓰는 파일에는 템플릿·작성 도구가 표시를 붙인다.

## 3. 읽기 호환

| 파일의 형식 | 플러그인이 하는 일 |
|---|---|
| 현재 | 그대로 |
| 옛것, 이전 도구 있음 | 읽고 경고한다. 쓰기 전에 옮길지 묻는다(`/dt-migrate` 또는 그 스킬의 merge 멈춤) |
| 옛것, 이전 도구 없음 | 읽고 경고만 한다(형식 검사가 오류를 경고로 낮춘다). 다음에 그 스킬이 다시 쓸 때 새 형식이 된다 |
| **플러그인보다 새것** | 쓰지 않고 멈춘다 — "플러그인을 업데이트하라". 읽기는 그 스킬이 정한다(정의서는 `versionTooHigh`로 멈춤) |

이전 도구는 **미리보기가 기본**이고 사람이 확인한 뒤 쓴다. 사람이 쓴 내용은 지우지 않는다 — 겹치는 절처럼 고를 것이 있으면 묻는다(`docs/refs/askquestion-principle.md`). 두 번 돌려도 결과가 같아야 한다.

## 4. 없앨 때

- 스킬·명령·설정 키·외부 도구 이름을 없앨 때는 **한 minor 동안 옛것과 새것을 함께 받는다** — 옛것을 쓰면 경고하고 새 이름을 알린다. 그다음 minor에서 없앤다. CHANGELOG에 두 번(경고 시작·없앰) 적는다.
- 외부 서비스가 날짜를 정해 없애는 것(예: Atlassian MCP v1, 2027-03-01)은 그 날짜까지 함께 받는다(`docs/refs/atlassian-mcp.md`).

## 5. 형식을 바꿀 때 할 일 (기여자)

1. `scripts/artifactSchemas.mjs`에서 그 종류의 `current`를 올리고, 옛 버전을 알아보는 판정과 이전 함수를 더한다.
2. 템플릿·작성 도구가 새 표시를 쓰게 한다.
3. 테스트: 옛 파일 → 이전 → 현재 버전 판정, 두 번 돌려도 같음.
4. `CHANGELOG.md` 미출시 절의 **산출물 형식 변경**에 무엇이 바뀌고 어떻게 옮기는지 적는다.
