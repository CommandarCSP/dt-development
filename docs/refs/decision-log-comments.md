# 결정 로그 주석

비즈니스 규칙은 개발하면서 계속 바뀐다. 현재 코드만 봐서는 지금 규칙이 어떤 사정의 결과인지 알 수 없고, 사람도 AI도 이미 버린 방식을 다시 제안한다. 결정 로그는 그 변천을 규칙이 사는 자리 바로 옆에 남긴다.

기본 주석 규칙(주석 없음, WHY만, WHAT 금지)은 그대로다. 이 문서는 **비즈니스 로직 레이어에 한해** 그 규칙에 한 갈래를 더한다.

## 적용 범위

| 레이어 | 경로 | 결정 로그 |
|---|---|---|
| BE Service | `src/**/*.service.ts` | 허용·권장 |
| FE Business Hook | `src/business/hooks/**/*.{ts,tsx}` | 허용·권장 |
| 그 밖의 모든 레이어 | — | 금지. 현행 인라인 WHY 주석만 |

Controller·Repository·DTO·View·Domain Component·Store Query·Page에는 쓰지 않는다. 비즈니스 규칙이 그 레이어에 있다면 주석이 아니라 코드를 옮겨야 한다.

외부에서 온 정책, 임계값, 예외 처리를 담은 함수는 **최초 구현부터** 로그를 단다. 첫 결정의 근거는 그때가 가장 정확하다.

## 형식

```ts
/**
 * 예약 확정 시점: PG 웹훅 수신 후
 * - 2026-03 · 초기: 결제 성공 응답을 받으면 즉시 확정
 * - 2026-09 · PROJ-412(정산팀): 웹훅 수신까지 보류로 변경.
 *   낙관적 확정이면 취소 환불이 정산 마감을 넘겨 수기 정산이 생김.
 */
async confirmReservation(...) { }
```

### 1. 첫 줄은 현재 규칙

지금 유효한 동작을 한 구절로 요약한다. 규칙이 바뀌면 이 줄을 **갱신**한다.

한 줄만 읽고 현재 동작을 알 수 있어야 하고, 아래 로그는 필요할 때만 내려 읽는다. 이 장치가 개수 상한을 없앨 수 있게 해준다 — 로그가 12줄이어도 읽는 비용은 첫 줄 하나로 고정된다. 첫 줄을 갱신하지 않으면 주석이 거짓말을 시작한다.

### 2. 항목은 시간순

오래된 것이 위, 최신이 아래. 표기는 `- YYYY-MM · 출처: 무엇을 바꿨나. 왜.`

출처는 Jira 키 또는 요청 주체(`정산팀`, `장애 대응`). 최초 항목의 출처는 `초기`.

### 3. 이유 없는 항목은 위반

```
- 2026-09 · PROJ-412: 확정 시점 변경
```

이것은 금지다. 기본 주석 규칙이 "태스크 참조는 커밋 메시지에 속하고 코드에서 썩는다"며 막던 바로 그 형태다. 출처는 이유를 **보강**할 때만 허용하고, 이유를 **대체**할 수 없다. 키만 남은 주석은 시간이 지나면 아무것도 말해주지 않는다.

### 4. 개수 상한 없음

항목 수는 제한하지 않는다. 뒤 항목이 앞 규칙을 완전히 대체했고 되돌릴 이유가 남지 않았을 때만 지운다. **애매하면 남긴다.**

## 정상 / 위반

### ✅ 정상

```ts
/**
 * 무료 취소 한도: 출발 48시간 전까지
 * - 2026-01 · 초기: 24시간 전까지. 경쟁사 기준을 따름
 * - 2026-05 · PROJ-108(CS팀): 48시간으로 늘림.
 *   24시간 기준에서 취소 분쟁 문의가 전체 인입의 3할을 차지했음.
 */
```

### ❌ 위반

```ts
/**
 * - PROJ-108: 취소 한도 수정          ← 시점·이유 없음 (규칙 2, 3)
 * - 2026-01 · 초기: 24시간 전까지
 */
```

```ts
/**
 * 무료 취소 한도: 출발 24시간 전까지   ← 아래 항목과 어긋남. 첫 줄 미갱신 (규칙 1)
 * - 2026-01 · 초기: 24시간 전까지
 * - 2026-05 · PROJ-108(CS팀): 48시간으로 늘림. 취소 분쟁 문의가 많았음.
 */
```

```ts
/**
 * 예약을 확정한다
 * - 2026-09 · 결제 상태를 확인하고 예약 상태를 CONFIRMED로 바꾼 뒤 알림을 보낸다
 */                                    ← WHAT 서술. 코드가 이미 말하는 것
```

## 블록 안에서도 그대로인 금지

단계 설명, 함수명 반복, 이유 없는 티켓 참조는 블록 안에 있어도 위반이다. 결정 로그는 WHY를 적는 자리이지 WHAT을 적는 자리가 아니다.

## 검사

`decision-log-format`(형식)과 `decision-log-scope`(범위) 룰이 형식만 기계 검사한다. **블록이 없는 것은 잡지 않는다** — 휴리스틱이라 오탐이 나고, 시달리면 형식만 갖춘 빈 블록을 달게 만드는 역효과가 있다. 이유의 품질도 검사하지 않는다. 사람과 리뷰어의 몫이다.
