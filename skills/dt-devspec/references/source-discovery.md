# dt-devspec §1 발견 — 소스별 절차

> `dt-devspec` §1과 `definition-author` 1단계가 따른다. 소스를 읽는 방법·도구·사전 점검·출처 표기는 `${CLAUDE_PLUGIN_ROOT}/docs/refs/ux-sources.md`가 정한다. 여기는 **읽은 뒤 무엇을 뽑는지**만 적는다.

목표는 소스 종류와 상관없이 같다 — **화면·기능 후보(SP 후보)** 와 **데이터를 주고받는 지점(IF 후보)**, 그리고 IF의 규칙 문장(필터·정렬·조건·검증)을 원문 그대로 모은다. 결과는 `.dt-devspec/<scope>/discovery.json`에 소스별로 남긴다(각 항목에 §5 출처 표기).

## 1. 기획 문서 (Notion · Confluence · PDF · Markdown · 일반 URL)

Figma가 없을 때는 이 절차만으로 정의서를 만든다.

1. **목차 먼저.** 제목·절 구조를 뽑아 화면·기능 단위를 찾는다. 단서: "화면", "페이지", "메뉴", "기능 목록", 화면 ID(예: `SCR_…`), 사용자 흐름("~에서 ~를 누르면"), 와이어프레임 그림 캡션.
2. **SP 후보.** 단위마다 이름·목적 한 줄·나오는 데이터를 적는다. 목차가 평평하면(긴 한 문서) 사용자 흐름 문장으로 나눈다. 나눌 근거가 약하면 하나로 두고 `ambiguous`로 표시한다.
3. **IF 후보.** 데이터를 보여 주거나(목록·상세) 바꾸는(등록·수정·삭제·업로드) 문장마다 하나. 같은 데이터를 여러 화면이 쓰면 IF는 하나로 합친다.
4. **규칙 문장.** 필터·정렬·페이지 크기·검증·권한·상태 전이 문장을 IF에 원문 인용으로 붙인다. 표·목록에 있는 필드는 DM 후보로 같이 적는다(§2의 D3 규칙대로 실제로 오가는 것만).
5. **빈 곳은 비워 둔다.** 문서에 없는 경로·타입·상태 코드는 채우지 않는다(G3). §2의 컨벤션 도출이나 §3 협의가 채운다.
6. **문서가 여럿이면** 같은 화면·기능을 이름으로 맞춰 합치고, 다르게 말하는 곳은 주 소스(`ux-sources.md` §2)를 따른 뒤 차이를 §2.5 입력으로 넘긴다.

토큰 가드: 긴 문서는 절 단위로 나눠 읽고, IF 후보가 없는 절(소개·용어집·변경 이력)은 목차만 남긴다.

## 2. Figma

1. **화면 발견(가벼움).** `figma.metadata`에 페이지 노드(예: `0:1`)를 줘 프레임 트리를 얻는다. 최상위 프레임이 화면 후보다.
2. **대상 화면 고르기.** 이름·글자 노드로 데이터가 오가는 화면(목록·폼·상세)만 고른다. 순수 정적 화면(안내·빈 상태·완료)은 트리로 충분하다 — 본문을 읽지 않는다.
3. **본문 읽기(무거움).** 대상 화면마다 `figma.context`를 **한 번** 부른다. 주석·규칙 글이 어디 있는지는 가정하지 않고 화면 전체를 읽는다.
   - `.dt.json`의 `uxSources.figma.annotationLayout`이 `right-panel`이면 §3의 판별로 주석 틀만 읽는다(토큰 절약). 기본값 `none`은 화면 전체다.
4. 읽은 글에서 §1의 3~4단계처럼 IF 후보와 규칙 문장을 뽑는다. UI 요소·스타일은 담지 않는다(정의서는 슬림 — 불변원칙 2).

## 3. `annotationLayout: right-panel` — 오른쪽 주석 틀만 읽기 (opt-in)

화면을 [왼쪽 UI] + [오른쪽 주석·규칙 글]로 그리는 팀을 위한 설정이다. `get_metadata`로는 주석 글이 자리 표시(`Description` 등)로만 나오고, 왼쪽 UI 본문은 IF 규칙에 필요 없으니 주석 틀만 읽는다.

1. 대상 화면 프레임을 `figma.metadata`로 열어 직속 자식을 본다.
2. 화면 폭 전체를 덮는 배너와, 왼쪽 UI 안에 들어가는 작은 오버레이를 뺀다.
3. 남은 것 중 가장 왼쪽의 큰 프레임을 왼쪽 UI로 보고, 그 오른쪽 끝(x+width)을 구한다.
4. 그 끝 너머에서 시작하는 큰 단일 프레임이 주석 틀이다. 예: 왼쪽 UI가 x 0~1920이면 x≥1920에서 시작하는 프레임. 이름(`Description` 등)은 양쪽에 다 나올 수 있어 믿지 않는다 — **x 범위**만 믿는다.
5. 찾으면 그 틀만 `figma.context`로 읽는다. 아래면 화면 전체를 읽는다(규칙을 놓치는 것보다 토큰이 낫다).
   - 오른쪽에 틀이 없다 · 주석 없는 화면이다 · 좌우로 안 갈린다(한 덩어리, 세로로 쌓임) · 오른쪽이 틀 3개 이상으로 쪼개졌다 · 조금이라도 애매하다.
6. 호출 한도는 그대로 대상 화면당 한 번(주석 틀 한 번 또는 화면 전체 한 번)이다.

## 4. 기존 스펙 (역합치)

`docs/specs/{pages,resources}/*/`의 leaf 스펙은 SKILL §1-b가 다룬다. 소스 종류와 상관없이 함께 읽는다.
