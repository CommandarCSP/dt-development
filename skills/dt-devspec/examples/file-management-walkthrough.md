# file-management dt-devspec 워크스루

> 이 파일은 **설명용** 워크스루입니다. 검증 대상이 아닙니다.
> 완성된 산출물 픽스처: [`sample-definition.md`](./sample-definition.md)

---

## 개요

file-management 기능을 예시로, dt-devspec 스킬이 멀티소스 경량 스캔 → FE/BE 경계 추론 → 협의 → 산출물 저장까지 어떻게 흐르는지 설명합니다.

---

## Step 1. 발견 + 타깃 deep-read

**입력 소스:**
- Figma 페이지 노드 `0:1` (파일 관리 화면 전체)

**발견 + 타깃 deep-read 방법:**

먼저 `mcp__plugin_figma_figma__get_metadata("0:1")`을 호출해 프레임 트리(id·name·type·위치/크기)를 가져와 스크린을 발견합니다(경량). 그다음 각 대상 스크린을 `get_metadata`로 까 직속 자식을 보고 **우측 주석 영역만 골라 `get_design_context`로 deep-read**합니다 — 화면이 [좌측 UI]+[우측 규칙 글] 구조라, 전폭 배너·오버레이를 제외하고 **좌측 UI 경계 너머의 큰 단일 프레임(예 SCR_FLE_01의 우측 주석 컨테이너 `409:28220`, x=2100)**만 긁어 검색·정렬·토글 규칙을 확보합니다(좌측 UI 1920×1083은 안 긁어 토큰 절감; 우측 식별이 불확실하면 통째 폴백). 확보한 규칙은 IF 계약에 반영하며, 페이지 내부 스타일·코드는 dt-spec 몫으로 남깁니다.

**스캔 결과 (요약):**

| 프레임명 | 판독 기능 |
|---|---|
| FileList | 파일 목록, 검색 바, 정렬 드롭다운 |
| FileItem | 체크박스, 파일명, 크기, 날짜 |
| DownloadArchivePanel | 선택 건수 표시, 압축 다운로드 버튼, 진행률 |

## Step 2. FE/BE 경계·인터페이스 후보 추론

스캔 결과를 바탕으로 책임을 분류합니다.

**분류 결과:**

| 기능 | 책임 | 신뢰도 |
|---|---|---|
| 파일 목록 조회·검색·정렬 | FE(표시) + BE(필터·정렬) | confident |
| 파일 선택 집합 (체크박스) | FE 전용 | confident |
| 비동기 압축 다운로드 | FE(트리거·폴링) + BE(작업 처리) | confident |
| 업로드 폼 | FE(UI) + BE(저장) | confident |
| 단건 파일 다운로드 | FE(링크) + BE(스트림) | confident |

**인터페이스 후보:**

1. `GET /api/files` — 목록 조회·검색·정렬
2. `POST /api/files` — 파일 업로드
3. `DELETE /api/files` — 복수 삭제
4. `GET /api/files/{id}/download` — 단건 다운로드
5. `POST /api/files/download-archive` — 비동기 압축 다운로드 요청

## Step 2.5. 충실도·협의 완전성 검증 (자동 정제 게이트)

§2 초안을 사용자에게 보여주기 전, 입력 원본(이 예시는 Figma deep-read 텍스트)을 ground truth로 검증 서브에이전트를 띄웁니다.

**1차 — A 충실도 ∥ B 협의완전성 (병렬):**
- **A**: 초안 IF-1(`GET /api/files`) 요청에 `sort`가 빠졌는데 원본 주석 `861:46544` "해당 컬럼 기준 오름/내림 토글"에 정렬 규칙이 있음 → **누락** 적발.
- **B**: 원본 `519:14674` "압축 다운로드 → 비동기 백엔드 압축 후 **메일 발송**"에서 메일 발송 책임이 BE인지 별도 알림 서비스인지 모호한데 초안 SP-3이 BE로 **조용히 단정** → `silentlyDecided` 적발.

**2차 — 교차확인(refute):** 두 발견 모두 원본 근거가 명확해 반박 실패 → `accepted`.

**자동 정제 + §3 큐:**
- IF-1에 `sort` 자동 채움(누락, IF=풀 자동) → `## 변경 추적`에 정제 로그 기록.
- SP-3 메일 발송 책임은 모호 분담 → **자동 안 하고 §3 큐**로(사용자에게 물음).

**결과:** 초안이 정렬 규칙을 회복한 채 §3로 넘어가고, 메일 발송 책임은 §3 질문 목록에 추가됩니다.

## Step 3. 협의·확정 (askQuestion)

dt-devspec은 ambiguous 항목과 전역 규약 미결 항목을 사용자에게 질문합니다.

**이번 예시에서 질문한 항목:**

1. **전역 규약 — ID 타입**: "파일 ID를 숫자형 정수로 할까요, UUID 문자열로 할까요?"
   - 결정: 숫자형 정수 (64비트), 클라이언트는 문자열로 처리

2. **전역 규약 — 페이지네이션 방식**: "offset 기반과 cursor 기반 중 어떤 방식을 쓸까요?"
   - 결정: cursor 방식

3. **IF-5 멱등성**: "동일 파일 집합에 대해 압축 다운로드 요청이 중복으로 들어오면 어떻게 처리할까요?"
   - 결정: 진행 중 작업이 있으면 기존 작업 ID를 반환 (멱등 처리)

4. **SP-3 메일 발송 책임 (§2.5 큐에서 이관)**: "압축 완료 알림 메일 발송을 백엔드(압축 작업)가 직접 하나요, 별도 알림 서비스가 하나요? §2.5 검증이 초안의 조용한 단정을 잡아 이 질문을 올렸습니다."
   - 결정: 압축 작업(BE)이 직접 발송 (별도 알림 서비스 미도입) → SP-3 비고에 반영, §2.5 큐 소진 완료

## Step 4. 산출/갱신

협의가 완료되면 dt-devspec은 다음을 수행합니다.

1. `buildDefinitionHeader.mjs`로 5줄 헤더 생성
   - `definitionVersion: 1` (신규)
   - `status: draft` (사용자 검토 전)

2. 본문 작성 (1.2 스키마)
   - `## 전역 규약` — 에러 포맷·ID 타입·날짜·페이지네이션·인증·멱등성 + **URL 컨벤션**(prefix `/api/v1`·복수형·CRUD 메서드)
   - URL 컨벤션 합의 → 각 IF 경로를 **결정론적 도출**(예: 목록 → `GET /api/v1/files`), 도출된 IF는 `컨벤션`으로 시작(`확정`은 생성 시점 불가 — BE 상향정합 T2/T3에서 승격)
   - `## 범위 분담` — SP-1~SP-3 표 (`관련 IF` 컬럼)
   - `## 인터페이스 합의` — IF-1~IF-7 표 (`합의 상태`(4단계)·`참조 DM`·`출처` deep-link·`from`-SP 컬럼). IF-7은 §3에서 물었으나 단서 없어 `미해소(질문완료)`
   - `## 데이터 모델` — IF 응답에 등장한 공유 shape만 `DM-1`(File)·`DM-2`(Activity), DM↔IF 링크
   - `## 변경 추적` — 날짜·결정 이력
   - 산출 종료 시 **능동 요약 알림** 1줄: `⚠ 미해소 1건·draft — IF-7 · /dt-devspec 재실행 권장 · ℹ 협의중/컨벤션 6건`

3. `docs/specs/definition.md`에 저장

4. `validateDefinition.mjs`로 자체 검증 → `{ valid: true, errors: [] }` 확인

## 재실행 시나리오

인터페이스가 변경되면(예: IF-5 응답 스키마 변경) 아래 흐름으로 재실행합니다:

1. 기존 `docs/specs/definition.md` 파싱 → 현재 내용 로드
2. 변경 후보와 diff 표시
3. 사용자 승인 → `definitionVersion` +1 갱신 후 저장
4. 재검증

## dt-spec과의 관계

dt-spec(페이지 스펙)·dt-bespec(리소스 스펙)은 `docs/specs/definition.md`가 있으면 **소프트 게이트**(§0)에서 소비합니다 — 없거나 엉성해도 막히지 않고 판정별로 분기(`consume`/`none`/`needsNormalization`/`corrupt`/`versionTooHigh`). 다만 정식 정의서가 있을 때만 FE/BE 일관성이 보증되므로, **페이지/리소스 작업 전 dt-devspec으로 정의서를 먼저 만들어 두길 권장합니다.**
