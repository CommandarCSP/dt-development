# 계약 요소 체크리스트 (SOT)

"스펙이 침묵했지만 구현이 결정해야 했던 계약 요소" 목록. 세 곳이 공유한다:
① auditor 워커의 침묵 수집 스윕(agents/auditor.md §2) ② 상향 정합의 대조 차원
(docs/refs/upward-alignment.md) ③ 재발 방지 환류의 승격 대상(SKILL §5).

## be (리소스/엔드포인트 단위)
- 정렬 기본값·소유권 (BE 정렬인가 FE 위임인가)
- 페이지네이션 방식·기본 크기
- 필터 기본값
- 에러 응답 body 형식 (상태코드 외 — 에러코드·메시지 구조)
- 입력 경계값 (필수·min/max·빈 문자열·최대 길이)
- 멱등성 (중복 요청 시 동작)
- 날짜·타임존·포맷

## fe (페이지/컴포넌트 단위)
- 빈 상태 / 로딩 상태 / 에러 상태 처리
- 정렬·필터의 클라이언트 측 처리 여부
- 낙관적 업데이트 여부 (mutation 중 UI)
- 포커스·키보드 동선 (클릭 가능 요소의 키보드 접근)
- 재시도 정책 (실패 시 재시도/안내)

## ux (런타임 관찰 단위)
- 상태 전이 중 중간 상태 (더블클릭·연타 방지)
- 뒤로가기 동작

## 수집 판단 기준 (과수집 가드)
스펙이 침묵했어도 구현 결정이 **계약면**(다른 쪽이 의존하는 관찰 가능 동작)에 닿으면 수집,
순수 내부 구현 디테일(변수명·내부 캐시·리팩터링 여지)은 수집하지 않는다.
