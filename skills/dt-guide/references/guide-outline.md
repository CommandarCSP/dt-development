# 참조: 사용자 가이드 절 템플릿 (사외 독자용, 한글)

> 종류: **참조 문서(지식)** · 소비처: `guide-author`. SOT: 본 문서. 스펙 §7-1. 문체는 `docs/refs/readable-writing.md` B1 「사외 사용자 가이드」 행.

## 원칙

- 독자는 제품을 **처음 보는 사람**이다. 개발 용어는 첫 등장에서 풀어 쓴다(C3). 2인칭('여러분'·'당신')은 피하고 필요하면 주어를 생략한다.
- **그림 한 장은 한 절에서만** 쓴다. 같은 화면이 4절(흐름)과 5절(화면 안내)에 둘 다 필요하면 4절에는 흐름 속 장면, 5절에는 화면 전체로 **다른 그림**을 쓰거나, 한쪽은 글로 참조한다.
- 없는 절은 **뺀다**. 빈 절을 남기지 않는다.
- 사내 시스템 주소·티켓 키·개발 환경 흔적은 쓰지 않는다(G5).

## 절

### 읽는 순서를 설계한다 — 세 덩어리

절 목록을 만들기 전에, 독자가 문서를 **세 덩어리**로 본다는 것을 기억한다. 순서가
이대로여야 처음 온 사람이 앞에서부터 읽다가 길을 잃지 않는다.

| 덩어리 | 무엇인가 | 독자의 상태 | 해당 절 |
|---|---|---|---|
| **들어가기** | 이 문서와 제품이 무엇인지, 쓸 준비를 갖추기 | 아직 아무것도 못 함 | 0~4 |
| **따라하기** | 하나씩 해 보며 익히기 | 배우는 중 | 5~6 |
| **찾아보기** | 필요할 때만 펴는 곳 | 이미 쓰고 있음 | 7~11 |

앞의 두 덩어리는 **처음부터 끝까지 읽는 글**이고, 마지막 덩어리는 **찾아 펴는 글**이다.
성격이 다른 둘을 섞어 쓰면 "이걸 다 읽어야 하나" 라는 인상을 준다. 특히 화면 안내(8절)는
화면 수만큼 길어지므로, 절 첫 줄에 **"필요할 때 찾아보는 곳입니다"** 라고 밝혀 둔다.

### 절

| 절 | 채우는 재료 | 없으면 |
|---|---|---|
| 표지 | `product` · `version` · `prep.systemRequirements` · 대표 화면 1장 · `<p class="cover-version">…</p>` | 필수 |
| (목차) | **쓰지 않는다 — 조립기가 절(h2)로 자동 생성한다.** 표지 다음 쪽에 들어간다 | 자동 |
| 0. 이 문서에 대하여 | 이 문서의 목적 한 문단 · 대상 독자(`prep.audience`) · 읽는 법(위 세 덩어리를 두세 줄로) · 문서가 다루는 버전 | 필수 |
| 1. 무엇을 하는 도구인가 / 이럴 때 씁니다 | README 목적, 시나리오 제목들을 "이럴 때" 불릿으로 | 필수 |
| 2. 설치 · 접근 | `prep.systemRequirements`, `prep.installAccess`, 첫 실행 경고(코드 서명 여부) | 웹 서비스는 "접속" 한 문단 |
| 3. 처음 설정 | `prep.accountProvisioning`, `prep.thirdPartyPrereqs`, `prep.pricingNotice`, 설정 화면 | 준비물이 하나도 없으면 절 삭제 |
| 4. 시작하기 전에 알아 둘 것 | `prep.knownLimitations` 중 **쓰기 전에 알아야 손해를 안 보는 것만** · 되돌릴 수 없는 동작 · 요금이 드는 동작 | 없으면 삭제 |
| 5. 5분 만에 한 바퀴 | 가장 짧은 시나리오 하나를 끝까지. 단계 5개 이내, 그림 2~3장 | 시나리오가 없으면 삭제 |
| 6. 기본 사용 흐름 | `scenarios` 순서대로 소절, 단계마다 화면 1장(`steps` 순) | 필수 |
| 7. 알아두면 편한 기능 | 시나리오에 안 들어간 `features` | 없으면 삭제 |
| 8. 화면 안내 | 첫 줄에 "필요할 때 찾아보는 곳" 명시. `screens`(publish) 각각: 목적 한 줄 · 주요 기능 불릿 · 그림 1장 · 진입 경로 | 필수 |
| 9. 데이터는 어디에 저장되나 (+ 전송 고지) | `prep.dataNotice`, 저장 경로 | **코드에서 전송이 보이면 절대 삭제 금지** |
| 10. 문제가 생기면 · 자주 묻는 질문 | 알려진 문제 + 대처, `prep.supportChannel`, 4절에서 못 담은 `prep.knownLimitations` | 지원 채널 없으면 "배포자에게 문의" |
| 11. 이 버전에서 새로워진 점 | CHANGELOG 이번 버전 항목을 사용자 말로 | CHANGELOG 없으면 삭제 |
| 용어집 | 본문에서 풀어 쓴 용어 중 **두 번 이상 나오는 것**만 | 3개 미만이면 삭제 |

시나리오가 하나도 없는 프로젝트(예: 화면 두셋짜리 단일 목적 도구)라면 5·6절을 빼고
8절부터 간다. 그때도 `covers`는 화면 전부를 가리켜야 한다.

**절 번호는 고정이 아니다.** 삭제된 절이 있으면 남은 절을 1부터 다시 매긴다 — 목차에
`4. …` 다음이 `6. …` 으로 나오면 빠진 쪽이 있는 문서로 읽힌다.

### 절 도입 한 줄

각 절 제목 바로 아래에 **그 절에서 무엇을 할 수 있는지** 한 문장을 둔다. 목차에서 절을
고른 독자가 제대로 왔는지 한 줄로 확인하게 하는 장치다.

## 마크다운 규칙

조립기의 렌더러는 **작고 일부러 좁다**. 쓸 수 있는 것만 쓴다 — 아래 둘은 렌더되지
않고 글자 그대로 PDF 에 나온다(게이트가 잡지 못한다).

- **HTML 태그를 쓰지 않는다.** `<kbd>Cmd</kbd>` 는 그대로 `<kbd>Cmd</kbd>` 로 보인다.
  키 조합은 `**Cmd + Shift + .**` 처럼 굵게만 쓴다. 예외는 본문에 직접 넣는
  `<div class="page-break"></div>` 와 표지의 `<p class="cover-version">` 뿐이다.
- **인용문(`>`) 안에 제목(`##`)을 넣지 않는다.** 굵은 글씨로 대신한다.

쓸 수 있는 것: 제목·문단·굵게·목록·표·인용문·코드 블록·이미지·링크.

## 그림 규칙

- 마크다운 `![캡션](shots/<SCR-id>.png)` 한 줄 + 다음 줄에 한 문장 설명(테마가 `p:has(>img)`를 캡션 블록으로 본다).
- `capture.mode: manual` → `shots/manual/<SCR-id>.png`. `mode: none` → 그림 자리에 안내 문장 한 줄("여기서 OO 계정 로그인 화면이 열립니다. 로그인하면 자동으로 돌아옵니다.").
- 표지 뒤에 `<div class="page-break"></div>`.

## front matter

```yaml
version: <package.json version>
manualShotsReviewedAt: <같은 값 — 첫 판>
covers:
  - item: S1
    section: 기본 사용 흐름
  - item: SCR-<slug>
    shot: shots/SCR-<slug>.png          # mode none 이면 shot: none
  - item: SCR-<hidden>
    guide: n/a
    why: <publish false 인 이유>
changelogCovers: [<이번 버전 굵은 제목>]  # CHANGELOG 가 있을 때만
```

`covers`는 인벤토리의 `publish: true` 항목 **전부**를 가리켜야 한다(G2 양방향).

`version`과 `manualShotsReviewedAt`은 둘 다 `x.y.z` 형식이어야 하고, `version`은 프로젝트 `package.json`의 값과 같아야 한다(G1). MINOR가 오르면 `manualShotsReviewedAt`도 올린다(G4).
