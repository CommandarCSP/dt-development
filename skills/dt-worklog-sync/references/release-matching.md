# 수정 버전(릴리즈/마일스톤) 규칙

Jira의 **수정 버전(fixVersions)** 필드를 프로젝트의 **릴리즈(마일스톤)**에 채우는 규칙의 SOT다.
릴리즈는 이 팀의 마일스톤이므로, 동기화하는 모든 이슈가 어느 릴리즈에 속하는지 드러나야 한다.

## 대상 — 부모 값으로 통일

| 이슈 타입 | 수정 버전 |
|---|---|
| 스토리 · 작업 · 버그 (부모) | 채운다 |
| 하위 작업 · 버그 하위 작업 | 채운다 — **부모와 같은 값** |

한 작업 묶음이 두 릴리즈로 갈라지지 않게 **부모 값으로 통일**한다. 하위 작업만 다른 릴리즈로 미루는 예외는 두지 않는다 — 그런 상황이면 작업 묶음 자체를 나눌 일이다.

### 버그는 작업 하위로 옮길 수 없다

버그와 작업·스토리는 **계층이 같다**(Jira `hierarchyLevel: 0`). 그래서 버그를 작업의 **자식이 될 수 없다** — 묶으려고 부모를 바꾸려 들면 실패한다.

버그는 Epic 아래 제자리에 두고 **수정 버전만 단다.** 버그를 쪼개야 하면 작업의 하위가 아니라 `버그 하위 작업`(별도 타입, `hierarchyLevel: -1`)을 버그 아래에 만든다.

### 제목에 버전을 적지 않는다

릴리즈는 **수정 버전** 필드가 그 자리다. 이슈 제목에 `[0.6.0]`·`(0.5.0, 미착수)` 같은 표기를 **넣지 않는다.**

필드를 쓰지 않던 시절엔 제목이 유일한 기록처였고, 그래서 한 작업의 하위 76개에 버전이 27번 박히는 일이 실제로 있었다(TASK-307). 필드로 옮기는 순간 제목의 버전은 중복이 되고, 릴리즈를 옮기면 제목이 거짓말을 시작한다.

이미 제목에 버전이 박힌 옛 이슈는 **건드리지 않는다** — 새로 만드는 것에만 적용한다.

## 릴리즈 목록 조회

공식 Atlassian MCP엔 프로젝트 버전 전용 조회 도구가 없다. **`getJiraIssueTypeMetaWithFields`**(대상 이슈 타입)의 `fixVersions.allowedValues`에서 목록을 얻는다.
- 각 항목: `{ id, name, description?, released, archived, releaseDate?, startDate? }`.
- `archived: true`는 후보에서 제외한다.
- **미출시(`released: false`)를 먼저** 보여주고, 출시 완료분은 목록 아래에 접어 둔다.

## 결정 순서

### ① 부모에 릴리즈가 있으면 — 그대로 상속

부모 스토리/작업/버그에 수정 버전이 이미 있으면 **그 값을 그대로 쓰고 사람에게 묻지 않는다.** 하위 작업에 같은 값을 넣고, 부모는 건드리지 않는다.

### ② 부모가 비어 있으면 — 사람이 고른다

후보를 **번호 목록**으로 제시하고 사람이 고른다. 모델이 고르지 않는다.

```
어느 릴리즈에 넣을까요?

1. [Insight] 검수 및 안정화 (~2026-09-11)   ← 추천
2. [Insight] 메모 기능 추가 및 수정 요청 사항 반영
3. [Chatbot] 시험운영 및 검수 (~2026-08-14)
4. [Strata] 0.3.0 배포
5. 맞는 릴리즈가 없음 — 새로 만들기
6. 릴리즈 없이 진행
```

- **추천은 표시만, 자동 확정하지 않는다.** 티켓 요약과 릴리즈 이름이 겹치는 정도로 1순위에 `← 추천`을 붙이는 선에서 그친다. 릴리즈 설명이 비어 있고 종료일이 지나 있는 경우가 흔해서, 이름 한 줄만으로 확정하면 근거 없이 찍는 것이 된다.
- 한 프로젝트에 제품이 여럿 섞여 있을 수 있다(`[Insight]`·`[Chatbot]`·`[Strata]` 같은 접두어). 접두어가 다르면 다른 제품으로 보고 섞지 않는다.
- 고른 값은 **부모에도 쓰고**(비어 있던 자리를 채움) 하위 작업에도 넣는다. 부모 갱신은 dry-run 표에 드러내고 승인받는다.

### ③ 맞는 릴리즈가 없으면 — 초안을 추천하고, 생성은 사람이

**공식 MCP엔 버전 생성 도구가 없다**(`createJiraIssue`·`editJiraIssue`는 이슈용, `fetch`는 ARI 읽기 전용). 그래서 스킬은 만들지 못한다.

1. 이번 작업 범위에서 **릴리즈 초안**을 뽑아 보여준다: 이름(제품 접두어 + 작업 묶음), 시작일·종료일, 한 줄 설명.
2. Jira 릴리즈 화면 링크를 함께 띄운다: `https://<site>/projects/<KEY>?selectedItem=com.atlassian.jira.jira-projects-plugin:release-page`
3. 사람이 만든 뒤 알려주면 `getJiraIssueTypeMetaWithFields`로 **목록을 다시 읽어** ②로 돌아간다.

프로젝트에 릴리즈가 **하나도 없을 때도 같다.** 조용히 넘어가지 않는다.

### "릴리즈 없이 진행"

사람이 그렇게 고르면 수정 버전을 비운 채 진행한다. **사람이 고른 결과일 때만** 비어 있을 수 있고, 모델이 알아서 건너뛰지 않는다.

## 기재 방법

- 생성 시 `createJiraIssue`의 `additional_fields`에 `{ "fixVersions": [ { "id": "<versionId>" } ] }`.
- 기존 이슈면 `editJiraIssue`의 `fields`에 같은 형태.
- **이름보다 id를 우선**한다(중복 이름·리네임에 안전). id는 `allowedValues`에서 얻는다.

## dry-run 표기

수정 버전 열에 세 경우를 구분해 적는다.

```
TASK-123 (부모)   (비어있음) → [Insight] 검수 및 안정화   ← 부모 갱신
TASK-124 (하위)   [Insight] 검수 및 안정화               ← 부모 상속
TASK-130 (부모)   [Strata] 0.3.0 배포 (변경 없음)
```
