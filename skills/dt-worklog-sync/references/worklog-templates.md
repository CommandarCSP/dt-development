# dt-worklog-sync 본문/코멘트 템플릿 (단일 소스)

스킬은 이 템플릿의 `{슬롯}`을 커밋·세션·수동 메모에서 채워 Jira에 쓴다.
모든 쓰기 호출에 `contentFormat: "markdown"`을 전달한다.

> **산출물 링크의 1차 위치는 산출물(Output) 커스텀 필드**다(`references/output-field-rules.md`) — 커밋/MR의 GitLab URL 자체를 그 필드에 멀티라인으로 기재한다. 아래 DoD 체크·코멘트의 산출물 링크는 보조(사람이 본문에서 바로 보라는 용도).
슬롯을 맥락에서 채울 수 없으면 임의로 지어내지 말고 `{확인 필요}`로 두고 dry-run에서 질문한다.
문장은 `${CLAUDE_PLUGIN_ROOT}/docs/refs/readable-writing.md`(읽기 좋은 글쓰기)를 따라 채운다 — 약어 첫 등장 풀어쓰기, 내부 용어 설명, 한 문장 한 개념.

## Description — 공용 (Sub-task / Story / Task)

```markdown
## 무엇을 (What)
{한 줄 요약 — summary와 중복 아닌, 작업 범위 1~2문장}

## 왜 (Why)
{배경·목적. 구두/메신저 요청이면 출처 한 줄(가이드라인 룰 6)}

## 어떻게 (How)
- {접근 방식 / 주요 변경점}
- {관련 파일·모듈}

## 완료 조건 (DoD)
- [ ] {검증 가능한 완료 기준}
- [ ] {산출물(커밋/MR/테스트결과) 첨부 — 룰 7}
```

## Description — Bug 변형

Bug는 How 자리에 재현·기대/실제 섹션을 끼운다. 나머지는 공용과 동일.

```markdown
## 무엇을 (What)
{결함 한 줄 요약}

## 왜 (Why)
{영향 범위·심각도}

## 재현 (Repro)
- {재현 절차}

## 기대 · 실제 (Expected / Actual)
- 기대: {정상 동작}
- 실제: {결함 동작}

## 완료 조건 (DoD)
- [ ] {수정 검증 기준}
- [ ] {산출물 첨부}
```

> Bug의 `Deployed→해결방법`, `Verified→검증방법`은 description이 아니라 아래 코멘트 템플릿으로 작성한다.

## Comment — 진행 업데이트 / 상태 전이 공통

```markdown
{진행 내용 자유 서술 — 무엇을 했고 다음은 무엇인지. 상태 전이 시 전이 사유를 첫 문장에}

**산출물**: {커밋/MR/테스트결과 링크}
```

규칙:
- 고정 헤딩 없음. 한 줄이든 문단이든 자유.
- 산출물 링크 줄은 권장 필수. 링크가 없으면 "링크 없이 진행만 기록할까요?"를 1회 확인.
- Bug `Deployed→해결방법` / `Verified→검증방법`, Sub-task `Done→산출물`도 이 같은 템플릿으로 작성.
